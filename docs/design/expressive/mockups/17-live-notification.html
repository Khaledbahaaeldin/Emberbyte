What we found out (sources at the end of the reply): 1. Android 16 "Live Updates" are the official way. A notification qualifies when it is ongoing, has a title, uses a standard, BigText, Call, Progress or Metric style, has no custom view, is not colourised, its channel is not "minimum", the app holds POST_PROMOTED_NOTIFICATIONS and requests promotion. The chip text comes from setShortCriticalText; it shows up to 96 dp, and text under 7 characters is shown whole. 2. Samsung does not have a separate API for apps. One UI 8 shows these same Live Updates in the status bar, on the lock screen and in the Now Bar. The user can switch it per app: Settings, Lock screen and AOD, Now bar (the path comes from forum reports, we must confirm it on the S24+). 3. Google lists what is allowed: an ongoing, user-started activity with a clear start and end (navigation, rides, delivery). Plain "ambient information" is explicitly not allowed. Emberbyte's live usage sits on that line, so the notification is pinned by the user ("Show live usage" is an explicit switch), the chip is dismissable, and we do not repost it after the user dismisses it.
The important finding about our code. Today the promotion request is only sent on Android 16 QPR2 (API 36.1), because setRequestPromotedOngoing was finalised there. A Galaxy S24+ on One UI 8 is Android 16 (API 36.0), so our app never asks for promotion there and no pill appears. On 36.0 the same request can be made through the extra Notification.EXTRA_REQUEST_PROMOTED_ONGOING, which Google's documentation lists as an equal alternative. That is the first thing to test on your phone, and the plan item for it is below.
Proposed work (new task, after widgets): • Send the promotion request on API 36.0 through the extra, keep the builder method on 36.1. • Add the "Allow live updates" check: canPostPromotedNotifications(), and a row in Settings that opens ACTION_MANAGE_APP_PROMOTED_NOTIFICATIONS; on Samsung a short hint about the Now bar switch. • Chip text per state (value left or "Over cap"), never colour alone, colours from the active theme. • Respect dismissal (setDeleteIntent): once dismissed it is not promoted again until the next day or the user turns it back on. • Prove it on your S24+ with a short dumpsys notification check and a photo of the status bar; the emulator cannot show Samsung's pill.
